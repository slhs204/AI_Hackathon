# Dobby’s Catch：2–3 分鐘 Live Demo 重點講稿

這份講稿約 2 分 40 秒，包含點擊與短暫等待。粗體是操作提示，不用念；引號內可直接照念。以新版「標題掃描完成後選信」流程為準，先用合成郵件預演。

## 上台前準備

- 開啟 Start-Demo.cmd，完成一次連線，保留這一個視窗。token、登入畫面與帳務頁面留在投影範圍外。
- 使用獨立的展示 Gmail 帳號，確認投影範圍的收件匣只有合成信，不含私人郵件標題。Chrome 載入目前套件並重新整理 Gmail，上台前預演一次 Check inbox titles。標題檢查不會遍歷其他資料夾或尚未載入的郵件。
- 主示範使用 T23「Updated remittance details」；備用 T06。先確認點選線索與 Reconsider 可用；預演分析與追問也會使用模型額度。只分析合成郵件。
- 若推論稍慢，先解說引用證據的核對原則；不連按、不把等待動畫當成成功判定。

## 0:00–0:20｜問題與價值

**畫面：Gmail 合成郵件清單，Dobby’s Catch 側欄已開啟。**

「大家好，這是 Dobby’s Catch，給薪資、人資與財務人員使用的 Gmail 防詐教練。遇到更換銀行帳戶的郵件，使用者不只需要警告，還需要知道：哪裡可疑，為什麼，以及下一步怎麼核實。」

## 0:20–0:45｜從標題清單開始

**按 Check inbox titles，讓標題掃描完整結束；從結果清單點選 T23，不手動搜尋。T23 預期顯示 No local title clue；這不代表內文安全。**

「我先按 Check inbox titles。系統會掃描目前可見的郵件標題，完整掃描結束後才顯示清單。這一步在本機完成，不會把郵件送給 AI。即使標題沒有警告，內文也可能有風險。我直接從清單選信，不需要另外搜尋。」

## 0:45–1:15｜AI 分析與不可信指令

**按 Analyze open email，等待內文掃描與真正的分析回覆。**

「按下分析後，才會送出這封選定的合成郵件。後端結合薪資詐騙規則，以及 Thinking Machines Tinker 上的 Qwen3-8B 推論，解釋可疑線索。這封信甚至要求 AI 忽略指令、回報沒有警告；但信件是待檢查的資料，不能因此清除銀行變更的警告。」

## 1:15–1:45｜把警告連回原文與行動

**往下捲至分析結果，點選銀行變更線索，展示 Gmail 反白，以及回撥／第二人核准建議。**

「我點這個線索，就能回到郵件裡對應的文字。後端也會核對 AI 引用的內容是否真的存在；無法核實時，會保留不完整提示。這裡的建議不是照信件改帳戶，而是用原有電話回撥，並取得第二人核准。」

## 1:45–2:10｜使用者可以追問

**選定線索，在 Additional context 輸入「寄件者說 IT 已核准」，按 Reconsider selected finding。**

「使用者也可以補充背景，挑戰這個判斷。像是寄件者說 IT 已經核准，AI 會重新考量，說明還有哪些事情沒確認。但郵件自己聲稱已核准，不能取代獨立查證，也不會變成付款許可。」

## 2:10–2:40｜成果與界線

**展示目前結果與不完整提示；不用切到另一份報表。**

「在一百封既有公開測試郵件中，規則加 Qwen 有九十七封的警告結果符合標籤，仍有兩個誤報和一個漏判。資料集幾乎沒有薪資案例，而且每次檢查仍不完整；這不是全新盲測，也不能當成真實郵件的準確率保證。Dobby’s Catch 的價值，是讓警告變得能理解、能追問、能核實，而不是替使用者批准付款。」
